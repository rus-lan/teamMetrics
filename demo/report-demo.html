Как читать цифры (важные оговорки)
  • Привязка задачи к спринту: вкладка «Спринт» относит задачу к спринту по интервалам членства в поле Sprint (задача могла заходить и выходить из спринта несколько раз), а персональная и инженерная статистика — по дате завершения задачи, попавшей в календарные даты спринта. Для одной и той же задачи эти два способа могут указать на разные спринты.
  • Определение «сделано»: вкладка «Спринт» считает задачу выполненной, если на конец спринта её статус относится к категории Jira «done» (с учётом списка отменённых статусов). Персональная статистика считает задачу выполненной по первому попаданию в один из именованных финальных статусов, включая предрелизные «To Test» и «Ready to Deploy». Число выполненных задач по этим двум вкладкам не совпадает и не должно сравниваться напрямую.
  • Throughput (день сдачи задачи): вкладка «Спринт» берёт день ПОСЛЕДНЕГО перехода задачи в категорию «done» внутри спринта, а персональная статистика — день ПЕРВОГО перехода в финальный статус. При повторных переоткрытиях задачи эти даты могут разойтись на недели.
  • Story Points: вкладка «Спринт» показывает значение поля на момент выхода задачи из спринта (реплей истории изменений SP), а персональная статистика — текущее значение поля на момент выгрузки отчёта. Если оценку меняли уже после спринта, суммы SP по двум вкладкам разойдутся.
  • Период персональной и инженерной статистики: с версии 3.0.0 он покрывает все анализируемые спринты (базовые + целевые), а не только целевые. Суммарные числа по людям и CI/CD поэтому шире, чем метрики одного целевого спринта на вкладке «Спринт».

03 Динамика команды

03.1

Метрики спринтов (Jira)

Commitment (SP)

Обязательство на старте каждого спринта и фактическая поставка к его концу, в Story Points. Столбцы построены по тем же величинам, что и плитки обзора: committed_sp и delivered_sp каждого спринта.

Performance (Say/Do), %

Поставлено / обязательство × 100 по каждому спринту. Пунктирная линия — цель 80%. Значения ниже — команда систематически обещает больше, чем поставляет.

Загрузка, %

Обязательство спринта относительно средней velocity предыдущих спринтов (SMA5), × 100. Пунктирная линия — 100%. Выше 100% — команда взяла больше своей средней скорости; ниже 80% — недогруз.

Изменение объёма (SP)

Из чего складывалось изменение объёма спринта: добавленные задачи, изменение оценок уже взятых задач и убранные задачи, в SP. Большие столбцы — нестабильный объём спринта.

Velocity (SP)

Velocity (= поставленные SP) каждого спринта и её скользящее среднее по 5 предыдущим закрытым спринтам (SMA5). Сходимость линий — стабильная скорость.

Throughput (задач)

Число задач, доведённых до «Готово» в каждом спринте (по дню последнего перехода в категорию «Готово»).

03.2

Динамика доставки (Jira + GitLab)

Разрез метрик по спринтам: видно, ЧТО менялось от спринта к спринту, а не только суммарные цифры за период. Пунктиром показан тренд (линейная регрессия). Задачи привязаны к спринту по дате завершения, MR — по дате merge, пайплайны — по дате создания, деплои — по дате завершения.

Throughput по спринтам

Сколько задач завершено в каждом спринте. Резкое падение к концу периода может значить, что спринт ещё не закончен; устойчивый тренд вниз — повод разобраться.

Cycle time по спринтам, ч

Если cycle time растёт от спринта к спринту — команда замедляется. Медиана устойчивее среднего к выбросам.

Rework по спринтам

Сколько раз задачи возвращались в работу в каждом спринте. Рост rework при росте скорости — сигнал, что качество с первого раза падает.

Rework rate по спринтам, %

Доля задач с хотя бы одним возвратом. Чем выше — тем больше переделок.

MR по спринтам

Сколько merge request'ов открыто и сколько дошло до merge в каждом спринте.

PR cycle time по спринтам, ч

Среднее время MR от открытия до merge. Рост от спринта к спринту — код дольше дожидается проверки/деплоя (выкатки).

Пайплайны и деплои по спринтам

Объём CI/CD-активности. Резкие всплески без роста выпускаемых задач — признак переделок и повторных запусков.

Успешность CI и деплоев, %

Доля успешных пайплайнов и деплоев. Падение при растущем темпе — качество досталось ценой стабильности.

Story Points по спринтам (сумма)

Сколько «стори-поинтов» (относительной сложности) команда закрыла за спринт. Падение — меньше комплексной работы закрыто за спринт.

Средние оценки на задачу по спринтам

Средняя сложность задачи и средние трудозатраты на тестирование. Каждый отдельный показатель читается только в сравнении с собственным baseline.

Средний вес MR (число файлов) по спринтам

Сколько файлов в среднем трогали за спринт. Чем больше — тем шире зона доработки.

09 Словарь и риски

09.1

Риски и на что смотреть

Высокий defect rate. 23.5% завершённых задач закрываются как баг/ошибка. Стоит больше тестировать и пересмотреть определение готовности.
Низкое покрытие тестами. Покрытие 55% — ниже 60%. Высокий риск регрессий при быстрых изменениях.

Главное правило: сравнивайте только с собственным baseline. Рост скорости при росте доли неуспешных пайплайнов / rework — тревожный сигнал, повод пересмотреть процесс, а не делать выводы.

09.2

Пояснения к метрикам (словарь для неспециалиста)

PR cycle time
Сколько времени в среднем MR ждёт от открытия до merge. Чем меньше — тем быстрее команда доводит изменения. Среднее чувствительно к «долгим» MR; медиана устойчивее.
Cycle time (Jira)
Время от взятия задачи в работу до закрытия. Ведущий показатель скорости доставки.
Throughput
Число завершённых задач за период. Объём результата команды.
Rework
Возврат задачи в работу после того, как её уже посчитали сделанной. Много возвратов = низкое качество с первого раза.
Defect rate
Доля завершённых задач, закрытых как баг/ошибка. Выше — хуже качество поставки.
Доля успешных пайплайнов
Сколько запусков CI завершились успешно. Падение при росте скорости — сигнал, что скорость досталась ценой качества.
Доля успешных деплоев
Сколько выкатов прошло без сбоя. Частота и стабильность деплоев — ключевые DORA-метрики.
Покрытие тестами
Доля кода, покрытого автотестами. Чем выше — тем ниже риск регрессий.
Story Points
Относительная оценка сложности задачи. Не переводится в часы напрямую: это мера объёма усилий в масштабе команды.
QA Estimation
Оценка трудозатрат на тестирование задачи (сколько усилий заложено на QA).
Вес MR
Сколько файлов затронул реквест (поле changes_count). Косвенно показывает объём доработки: чем больше файлов — тем шире зона изменений.
Baseline (P0)
Исходные показатели за первый замеряемый период, с которым сравниваются последующие. Позволяет смотреть на динамику, а не на разовые значения.
Velocity
Сколько Story Points команда фактически поставила за спринт. Основа планирования следующих спринтов.
Velocity SMA5
Скользящее среднее velocity по пяти предыдущим закрытым спринтам. Сглаживает разовые всплески и провалы.
Performance (Say/Do)
Отношение поставленного к обещанному на старте спринта, в SP. 100% — сделали ровно что обещали; цель — от 80%.
Загрузка
Обязательство спринта относительно средней скорости команды (SMA5). 80–100% — здоровая загрузка; выше — перегруз, ниже — недогруз.
Изменение объёма
Насколько менялся состав спринта после старта: добавленные и убранные задачи плюс изменения оценок, относительно обязательства.
Прогноз Monte-Carlo
Симуляция: тысячи случайных «проигрываний» будущего на основе прошлых дневных закрытий. Даёт не одну дату, а вероятностные сроки (P50/P85/P95).
CV (коэффициент вариации)
Мера нестабильности потока: разброс недельных сумм закрытий относительно их среднего, в процентах. Выше 50% — прогнозу доверять осторожно.

09.6

Предупреждения и ошибки

Коды предупреждений и ошибок отчёта (WARN_*, ERR_*)

КодЧто означает
WARN_BASELINE_SHORTЗакрытых спринтов для базы меньше 5 — SMA5/загрузка считаются по имеющимся.
WARN_CHANGES_COUNT_UNAVAILABLEGitLab не отдал число изменённых файлов ни по одному MR — вес MR показан как «нет данных».
WARN_COMMITS_UNAVAILABLEGitLab не отдал число коммитов ни по одному MR — метрики коммитов показаны как «нет данных».
WARN_DIFF_STATS_UNAVAILABLEGitLab не отдал размер диффа ни по одному MR — средний размер диффа показан как «нет данных».
WARN_DIVISION_BY_ZEROЗнаменатель формулы равен нулю — метрика обнулена.
WARN_OUTSIDE_SPRINTSЧасть записей завершена вне всех анализируемых спринтов и не попала в разрезы по спринтам.
WARN_SPRINT_ACTIVE_PARTIALВключён активный спринт — его метрики промежуточные.
WARN_TASK_CYCLE_TIME_UNAVAILABLEНи у одной задачи нет вычислимого времени цикла (нет перехода «В работе» → финальный статус) — cycle time задач показан как «нет данных».
WARN_THROUGHPUT_UNSTABLEПоток нестабилен — относитесь к перцентилям с осторожностью.

Технические коды запросов к GitLab

КодЧто означает
FILTER_REJECTED_FALLBACKGitLab отклонил фильтр по дате — деплои получены без фильтра и отобраны на стороне инструмента; числа корректны, запросов ушло больше.
HTTP_500Не удалось получить MR этого автора в этом проекте — его данные по MR неполные.
NOT_FOUNDПроект не найден в GitLab — пропущен целиком.
PAGINATION_LIMITСписок деплоев обрезан по лимиту страниц или времени — числа деплоев и их успешность занижены, не читайте их как полные.

В самом отчёте предупреждения всегда показаны текстом; этот справочник — для чтения report.json и логов.
